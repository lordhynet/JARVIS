# Intelligence quality gate v1

offline-v1.json has 48 synthetic, recorded cases: 12 each for coaching, supplied-reference research grounding, tool choice and refusal. Its checkers validate structure, per-sentence evidence, source allow-lists, expected tool/decision, required/banned content and cost per case. Every future provider/model change must pass this gate alongside the existing integration tests. No model route or price is changed by adding the gate.

Run the offline test class with `dotnet test --filter FullyQualifiedName~IntelligenceEvaluationTests`. Offline costs are recorded synthetic fixture values, not charges or measured model quality. Research fixtures evaluate reasoning over explicitly supplied synthetic excerpts; they do not measure live web-search coverage. This finite gate cannot prove overall quality or semantic entailment; human review and separately authorised provider evaluation remain necessary.

The optional owner harness is `scripts/run-intelligence-eval.ps1 -CoreBaseUrl https://your-core/`. Its default is offline. It uses process-only JARVIS_CORE_KEY/JARVIS_OWNER_KEY and saves the returned report; it never prints credentials or bypasses certificate trust. The endpoint needs the separate owner credential and manual origin.

Paid mode additionally requires owner-configured `Intelligence:EvaluationsEnabled=true`, `-RunPaid -ConfirmPaid` and explicit request cloud consent. It uses the existing Agent profile/JSON adapter and budget ledger, with pre-dispatch quotes bounded to USD 0.02 per case and USD 1 across the run's cumulative reservation envelope (48 cases at the per-case ceiling fit within it). Global GBP and lane limits still apply. Model/rate-card settings are unchanged. A request ID binds each case operation; completed cached cases can be reused, while pending/failed/unknown calls are not automatically replayed. Reconciliation blocks continuation. The paid mode has not been run against a live provider in this implementation run.
