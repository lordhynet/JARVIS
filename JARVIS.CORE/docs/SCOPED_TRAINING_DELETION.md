# Question-scoped training deletion

TrainingService delegates to the existing IRuntimeStore contract. Its default cohesive callback and PostgreSQL override share TrainingDeletion.Decide. Missing or already-deleted attempts return false before revision validation; a live attempt requires a matching positive revision. Tombstones retain practice/source metadata and sequence, increment revision and clear answer/assessment content and the canonical assessment pointer. Existing operation receipts remain unchanged; there is no new deletion identity, history, counter, API or service.

PostgreSQL retains the privacy/epoch gate and root writer lock, one context and SaveChanges/commit. A live target is selected by primary key and validated before any projection or cold content is read. The correction and deletion ports share one materialized question-local projection reader and card writer: baseline/membership/card primary keys, question-attempt expression predicate, selected review Event/request/sequence metadata. Replay Result bodies and full learning/training units are not loaded. Partial inputs never enter complete-unit diff. Missing baseline means deletion still cleans up its source without recreating learning authority; an ordinary missing card rebuilds only from a live baseline. No global sequence/audio access.

Deletion also runs the existing ReasoningLifecycle.Retire over canonical cold state: retire the scope, remove matching provider results, clear provider-attempt fingerprints and mark SourceDeleted while retaining route/reservation/charge metadata. The existing financial ledger is unchanged. This implementation intentionally reads and serializes the full cold document with the existing codec. Cold reasoning storage remains a separate dependency; this is not cold-free deletion or 50 ms acceptance. No parallel reasoning projection or JSON patch protocol is introduced. Fixed deletion phases expose residual reasoning hydration/retirement and cold serialization separately.

Projection and serialization complete before applying tracked mutations. One transaction covers the tombstone, derived card and reasoning cleanup. No-op deletion reads no learning or cold content and saves nothing. Tests compare complete default/PostgreSQL state, preserve receipt and financial metadata, exercise missing baseline/card and malformed selected inputs, unrelated learning/training poison, concurrent correction/manual review, epochs and rollback after SQL save, including cancellation. Real PostgreSQL runs in CI; large-volume benchmarks and independent source review remain separate gates. The migration/release recovery and owner-entry gates are unchanged.
