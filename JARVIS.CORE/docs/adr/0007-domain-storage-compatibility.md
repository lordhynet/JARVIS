# ADR 0007: Preserve domain storage and complete legacy aliases

18 November 2026. Item 6 of the version 2 run plan.

The requested domain storage already exists. DomainDefinitions, immutable DomainVersions, DomainCapabilityBindings, UserDomainState, DomainApprovals and DomainAuditEvents are relational, introduced by the existing DomainRegistry/DomainApprovalRisk migrations. Normalized validated keys and workflow keys have unique indexes. Draft request IDs and approval receipts are idempotent; the privacy/runtime lock serializes multi-host changes. Activation/rollback switch the approved version atomically, disabling retains data, and export/erasure includes the registry. Unknown dependencies may be kept as honest draft requirements, but activation refuses uninstalled capabilities, unsupported versions and external privileges. Adding duplicate tables or rewriting these migrations would be a regression.

The remaining gap is learning-enum compatibility. Activity aliases already existed; LearningDomain did not have a complete registry mapping. Add code-owned typed aliases for all eight ActivityType and eleven LearningDomain values. Six missing installed study domains are seeded for C#/.NET, distributed systems, databases, API security, production operations and payments/finance. Existing language, interview, algorithm, system-design and communication domains are reused. Existing enum values, stable IDs, immutable manifests/hashes, disabled states and owner preferences are not rewritten. Missing seeds use the existing additive seeding path; an existing owner domain at a key is never overwritten.

IDomainCatalog.ForLearning and IDomainRegistry.ResolveLearningAsync/ResolveActivityAsync expose typed compatibility. The owner-only /api/domains/aliases metadata endpoint makes the mapping reviewable. Ordinary string-key resolution keeps its existing behavior, so a user-defined key is not silently redirected by a new string alias.

The canonical manifest serializer is unchanged in this slice. Tests verify every old enum resolves, fresh seeding does not replace stored versions/preferences or reactivate disabled data, and the existing relational restart/concurrency/approval/refusal/rollback tests remain applicable. No additional migration, package, service or policy engine is needed. The domain factory still needs scoped study guidance, owner knowledge references and scoped memory in Item 7; those are not claimed by this storage slice.
