# Scoped learning-card creation

LearningService.CreateAsync delegates to an existing-store creation port. The default implementation keeps the original cohesive callback, while PostgreSQL inserts only the new canonical Learning row. A shared preparation method preserves domain validation, text trimming/limits and default scheduling metadata; identity/time are supplied inside the write boundary. Existing HTTP request/response and non-idempotent behavior remain: there is no request ID, so no silent replay or retry is introduced.

The PostgreSQL path keeps the privacy SHARE gate and the same RuntimeDocuments singleton FOR UPDATE writer lock as other runtime/session/manual-review commands. It samples the clock after the lock, stores exact timestamp provenance in canonical JSON, and projects UTC DueAt through the existing index. It does not hydrate other cards, reviews, baselines, sequence state, cold data or audio. Lock-wait and commit telemetry use existing instruments with fixed non-private labels. Cancellation, stale epochs and errors roll back the transaction. The root is locked without rewriting its payload/fingerprint.

No schema, route, client, identity/policy, provider, Forge activation or protected-data permission changes. This is an existing JARVIS learning capability used by projects, not a Forge-specific store. Assessment correction/rebuild, learning removal and history remain separate measured work before PF-05 volume. Synthetic matched callback/scoped creation measurements do not replace the earlier generic stability-edit or manual-review measurements, and are not lock-contention or hardware guarantees.
