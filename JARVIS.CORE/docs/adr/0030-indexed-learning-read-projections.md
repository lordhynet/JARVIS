# Async learning read projections

FG-00-Q1 extends existing IRuntimeReader projections; no new service, database entity, scheduler or learning authority. ReadLearningItemAsync fetches one canonical card. ReadLearningItemsAsync supports the existing uncapped learning list response, sorted by exact DueAt, without hydrating reviews/baselines/sequences/cold or audio state. ListLearningItems CQRS now dispatches this narrow port. Existing history and mutation/replay callbacks remain unchanged. Default methods support existing memory/test readers; GuardedMemoryRuntime supplies its existing epoch for due pages.

PostgreSQL reads use async EF/Npgsql queries inside the existing repeatable-read transaction and shared privacy gate. They do not acquire a writer lock, mutate runtime state or bypass epoch/erasure checks. JSON remains authoritative, preserving offsets/ticks and validating card identity against its row key.

ReadDueLearningPageAsync is an internal technical iterator, **not a public cursor or canonical scheduling order**. It orders candidates by stored microsecond index timestamp and UUID. Maximum page size100, plus one lookahead; CandidatesRead records transferred rows. Cursor binds the original cutoff and privacy epoch; mismatches fail. Each page is a fresh snapshot, not a snapshot lease across calls. Updates may move items between pages. Cursors are backend-specific and must never be persisted or shared across stores: PostgreSQL and .NET use different UUID tie orderings. Keep this technical type out of Jarvis.Contracts and public APIs.

The legacy SQL JSON timestamp cast can round while Npgsql truncates. Candidate selection uses a ceiling-microsecond superset and exact JSON DueAt filtering. Cursor advances after the last scanned candidate, including false positives, so an empty Items page with a non-null Next must still be followed. Raw index order can differ from canonical order within precision bins; do not substitute this iterator for exact top-N scheduling in existing voice/review flows. The public list retains exact canonical sorting. Missing index timestamps fail bounded paging closed; legacy list reads include null-index candidates and use canonical JSON.

The existing (Kind,DueAt) index supports selective due queries; UUID tie sorting may inspect more server rows than the bounded transferred window. Capture actual plans, not a claim that every possible same-stamp population is scanned in constant work. No extra index is added without measured need. Per-card queries use the existing (Kind,Id) primary key.

Acceptance: async-only query interception, isolation from unrelated histories/future payloads, bounded transfers, precision/offset/tie/empty-page behavior, epoch/cutoff fencing, query non-mutation, legacy query compatibility and synthetic1k/2k/10k plans/latencies. Full existing regression suite runs in CI; no live database/provider call.

This does not close the already-triggered single-card **write** p95 target (<250ms); the current cohesive mutation/replay loader remains synchronous. FG-00-Q2 must optimize those paths without breaking assessment correction, review replay, baseline membership, sequence allocation or atomicity before PF-05 volume. The separate hot-runtime <50ms gate and mixed maintenance-load limitations remain distinct; no hardware latency claim.
