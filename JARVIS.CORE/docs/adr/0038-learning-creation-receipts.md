# Durable optional learning creation identity

Extend JARVIS's existing CreateLearningRequest and learning store, not a Forge-specific card/history engine or generic idempotency service. Optional RequestId omitted preserves the existing non-idempotent manual behavior and response shape. Empty ID is invalid. Idempotent HTTP requires the existing explicit data-epoch header, and trusted callers require a captured PrivacyContext epoch. Never silently refresh/replay a stale request. The owner-only route/policy is unchanged.

CreationReceipts is a new closed collection kind in existing RuntimeLearningRows and the existing logical/lazy learning unit. The active immutable receipt binds request ID/epoch, versioned normalized-domain/prompt/answer SHA256 and the original LearningItem result. Owned UTF8 fingerprint bytes are cleared; no keyed MAC is introduced for ordinary canonical learning data. This does not authorize protected-class Forge text to enter learning. No-ID scoped PostgreSQL creation avoids receipt I/O. New card and receipt commit atomically under privacy SHARE then the existing runtime singleton writer lock; memory uses its existing boundary. Shared decision/apply logic preserves default/composite paths and initial scheduler metadata.

Read the receipt before creating a new identity or sampling time. Until retirement, identical retry returns the original result after correction, ordinary card removal, restart or a competing host, without resurrecting/modifying the card or allocating a sequence. Changed normalized input409; stale epoch409. This reply is historical evidence, not proof the card remains current/active. Future Forge producers must resolve current programme/domain/source permissions inside their existing composite transaction before replay/action; no producer is enabled here.

Recording privacy deletion retires relevant receipts in the same existing purge transaction: affected card IDs, stored source recording and known recorded-question lineage are reused. A question UUID is not a recording UUID; current practice/card/review lineage and, only for orphan question-only results, available transcript metadata resolve it. Legacy deletion with no such receipts need not reparse transcripts. A retired record stores only RequestId/Epoch/Status/RetiredAt: original result, content hash and fingerprint version are removed. Replay410 with learning_creation_retired occurs before payload comparison. Retrying cannot return recording-derived words. Whole-Core erasure clears all receipts through the existing epoch boundary.

Owner export adds optional CreationReceipts, omitted when empty. Active entries expose original CreatedAt/CardId/Result; retired entries omit those and expose RetiredAt and minimal identity/status. Fingerprints are never exported. These are authorized plaintext owner exports, subject to the existing private download advice; they are not agent/display/event/cache projections.

The existing privacy retention selection/apply pipeline also retires active receipts whose original Result.CreatedAt is strictly older than AsOf minus RetentionPolicy.CreationReceiptDays (default30, valid1–3650). Preview/job CreationReceipts counts denote original payloads retired; full-erasure counts include all removed receipt rows. Zero counts are omitted. Retirement removes the original result and fingerprint, preserves minimal identity/epoch/status/RetiredAt and returns the same410/code before comparing retry content. Current canonical cards/reviews/history remain unchanged; retired rows prevent duplicate creation and remain until full erasure. Repeated sweeps preserve the first retirement time. Ordinary card removal alone still allows replay until retirement.

Retention remains disabled by default. The existing enabled worker or an explicitly confirmed manual sweep applies this policy; this is not an implicit wall-clock TTL on reads. Existing UTC daily cutoff/sweep cadence can delay age retirement. No auto-enable, new worker, live setting or migration is introduced. Policy fingerprints include the new setting, so old previews require refresh.
