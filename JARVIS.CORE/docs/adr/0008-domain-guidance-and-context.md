# Domain guidance and owner context

The domain factory, existing registry tables, budgeted text adapter, workflow catalogue and exact owner approval remain the only creation path. This change adds optional study guidance and owner knowledge references to manifest v1. Null optional fields are omitted individually, preserving canonical bytes, installed version IDs and hashes of existing manifests. Original fields retain their previous serialization.

Core binds the original owner request as study guidance after validating a model draft. A model cannot supply this field or mint source references. Guidance is untrusted data in the user context, never a system prompt or permission. Reserved executable, provider, tool and data-class fields remain forbidden. Requested missing capabilities remain visible unmet dependencies. A URL is a clean HTTPS reference only: no retrieval, verification or claim of trusted legal or medical evidence. Imports must already exist; manifests store their IDs, never their contents. A later deletion leaves an inert reference and prevents retrieval.

Owner memory extends RuntimeState and the existing deterministic ContextSelector. It is not a new retrieval or orchestration engine. An owner can save a note or an exact bounded excerpt of a stored import or unrestricted Core-captured user turn. Source IDs, hashes, session, server time, expiry and sensitivity accompany the text. Restricted and retired speech is refused. The request cannot replace canonical source text or classify private sources Public. Writes compare the resolved domain version and revision again within D2, under the privacy epoch.

Assisted work uses at most five ranked memory records within 6,000 UTF-8 bytes and three 1,200-character import excerpts. This requires explicit run cloud consent, the same active version and a General domain. Research has no private scoped memory or import excerpts. Sensitive records remain local. Shared coaching context still has its separate manifest switch, and sensitive domain approval also suppresses it. Templates remain authored and free of provider calls.

Deleting a source removes derived memory and invalidates referring task outputs, provider caches and action authority. Expiry participates in retention preview and application. Export includes memory; full erasure clears it. Disabling a domain or parent (including user-state disable) cancels active domain runs in the same storage transaction while retaining notes and immutable versions. A late provider response cannot publish, and financial records are preserved.

The lifecycle audit also closes an action-delivery edge case: every Agent-origin device command requires its current proposal metadata. Removing proposal metadata can no longer fall back to the legacy manual confirmation path.

No new packages, provider/model changes, live source requests, installation or deployment are involved.
