# Public travel push through the existing outbox

Status: locally implemented; source review and physical phone acceptance pending.

The existing outbox, subscription authority, claim/retry/deduplication and encrypted Web Push transport are reused. The dispatcher supplies the full notification to the sender. Only the Travel category with code-owned route authority and a bounded public summary may include that summary in its encrypted payload. Every other category uses the generic private-inbox message regardless of its title or PublicSummary field. No saved route names, stops, owner IDs, route authority or private results are included in the push payload.

Travel authority is created inside an active route window. Core bounds expiry to the earlier of thirty minutes and that route's next inactive minute. Route edits/deletion expire outstanding authority in D2. Dispatch checks delivery/read state, start and expiry, current browser fingerprints, and Travel:NotifyWhenAgentsPaused (default true). Quiet hours are bypassed only for this bounded travel authority. Pending travel cannot be released by the generic agent ticker. Browser revocation, legacy migration-flag behavior, retry claims and per-subscription notification IDs are preserved.

The sender bounds transport TTL to remaining travel freshness, at most five minutes. The service worker additionally discards expired, malformed, oversized or control-character travel bodies. Generic categories cannot render server-supplied personal text. An already accepted external push cannot be recalled atomically by a later route edit; operating-system scheduling, client clock skew and notifications already displayed remain device acceptance considerations. No delivery latency is claimed without a physical owner check.

POST /api/travel/simulate uses the existing Owner policy. Travel:AllowSimulation defaults false, and Production always refuses it even when set true. The caller must be a manual owner client, choose a saved line within its active window and use one of four fixed synthetic states. Arbitrary text/URLs are refused. Two distinct requests are needed for confirmation. One-day bounded request receipts are persisted in TravelMonitorState JSON, so replay does not count as another observation or duplicate the outbox after restart. Reusing a request ID with different input is a conflict. Simulation notices are explicitly labelled Simulation and use the same transition, outbox and Web Push path. A live poll claim excludes simulation. No additional schema migration or Android screen is required.

After review, owner setup uses private TfL:AppKey and the existing Push:Enabled, Subject, PublicKey and PrivateKey settings. Configure routes in Daily briefing, use Chrome at the trusted Tailscale DNS address, and enable browser notifications under Connections. Confirm disruption and recovery on the actual S24/S22 before recording latency. Simulation must remain disabled in Production; its device rehearsal needs an explicitly authorized non-Production environment. No live third-party call, private configuration change, deployment, image build or installation was authorized for this run.
