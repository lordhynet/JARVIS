# Typed protected capacity-day payload

ForgeCapacityPayload is the versioned plaintext body for the existing encrypted ForgeCapacity row, not another database entity, calendar adapter or planner. Its private date/routine patterns, classifications, note, consent and owner-reported provenance stay inside the existing padded envelope. No public Contracts, routes, handlers or key/protector DI are added. A capacity row represents a dated configuration; weekly/default recurrence and editor composition remain future work.

Nullable net usable minutes, buffer and block list preserve distinct unknowns. Null obligations mean not supplied; an empty list explicitly means none. Zero minutes are known zero. No planning projection is returned while buffer or obligations are unknown, even with known net minutes. With known constraints and unknown net, the existing private projection remains unknown and cannot allocate. Missing origin/observed-at/classification remains null; no estimated week or invented work/sleep schedule. Consent must be explicit; observed-at cannot be future or a missing-value sentinel. Notes are bounded/trimmed and unknown whitespace becomes null.

Prepare delegates temporal/range/overlap/DST/clipping checks to the existing ForgeCapacityProjection.ForDay. Validation-only lower bounds for unknown constraints are never exposed as a projection. Typed blocks are defensively copied and ordered by actual instants for stable request comparison; original unclipped local intent is retained. Paused owner edits remain valid while the existing projection stays non-allocatable. The caller still rechecks programme revision/epoch within the existing transaction before committing any plan or record.

The payload is plaintext only within an authorized request and may serialize solely for protection or explicit authorized owner export. The prepared wrapper and allocator projection reject JSON transport. Strict unknown-member handling and explicit payload version refuse silently dropping future/private fields. Use the existing padded codec and scoped typed reader; do not cache/log/model/display payload objects. Managed-memory limitations remain those in ADR0032.

This is not entry-ready. E1 authorized decrypted export of every retained protected revision, D1 operational database-plus-retained-key recovery, owner step-up and retention remain prerequisites before a real entry endpoint ships. Baseline/check-in payload, weekly editing and authorized export/command integration remain separate work. Synthetic payload/storage tests do not satisfy operational recovery or hardware acceptance.

K1: record equality on IReadOnlyList compares references. Future commands must serialize the same normalized typed request (including original request ID/expected revision) in canonical property order and compare using the stored retry MAC/context, never payload==. A test proves equivalent reordered/trimmed inputs match the same MAC while changed request/value/context do not. This is the comparison contract, not an implemented durable command service.

K2: WithPolicyQuietHours composes an authorized current projection with already-resolved JARVIS quiet intervals converted into the programme zone/explicit offsets. It validates/clips with ForDay, unions overlapping/touching owner/policy intervals by actual instants, then counts blocked minutes once. Owner net is already net: preserve it if feasible, otherwise cap to remaining day minus the union and existing buffer; never subtract quiet duration again from that net. Unknown/zero/paused semantics remain. Missing policy intervals fail closed, explicit empty means no extra quiet period. If the declared buffer cannot fit, fail rather than invent zero buffer or alter owner configuration. Scope/revision/timezone are checked; output remains the existing JSON-blocked private type. The PF-08 allocator still must resolve current global policy and invoke this helper before scheduling; no allocator or policy setting is wired/changed here. Weekly defaults/day overrides remain K3 editor work.

U1: public owner configurations retain the64-block limit; only the derived union accepts up to128 disjoint blocks from64 owner plus64 policy intervals. U2: a minute cap is not a feasible schedule. PF-08 must place activities inside actual unblocked intervals and recheck current capacity/programme/epoch/policy before committing, not rely on total minutes alone.
