# ADR 0021: Private practice from recorded interviews

Status: implemented for source review; physical acceptance and release gates remain outstanding.

## One source and captured answers

The existing interview import remains the only store of recorded transcript text. R3 uses ImportService.Review's question extraction on labelled interviewer segments, with their existing capture intervals. It considers at most 30 question-bearing lines, each at most 1,200 characters. Multiple questions in one capture interval can share the same candidate Me answer; there are no fabricated word timestamps or precise question/answer boundaries. Unknown phone segments are excluded until the owner labels them. Relabelling cannot turn an interviewer loopback track into playable Me audio.

Original answer delivery uses the existing text/speech heuristics over whole capture intervals: word pace is an estimate, fillers are text candidates, opening score is a text heuristic, and acoustic pauses are unavailable. New-answer delivery uses the normal captured turn and its actual available Core timing. The same existing English checklist is shown before and after; marker coverage is not a competence or factual-accuracy grade. Shared words match real Story Bank content, not field names. Up to three current, exact-range owner-supplied source claims per matched story are shown; this is traceable supplied evidence, not independent verification.

An owner selects practice or recap in the unlocked dashboard. A dedicated, generically titled MockInterview conversation is created, and the existing VoiceCoaching lifecycle stores only recording/transcript/revision/question references, progress, consent time and captured-turn IDs. Private question text is resolved from the current import. A lost start response reuses the same operation ID. A failed bind may leave an empty conversation containing no private source text. Source revision changes require fresh practice rather than silently changing its questions.

Everyday voice resumes with the existing core_coaching current action, asks each real question in JARVIS's normal voice and waits. Answer requires separately captured, canonical, unrestricted Core speech matching the latest session message; typed/generated/restricted answers are refused. Canonical turns and conversation memory remain in the normal stores; no new practice audio is saved. Answers advance once, survive restart, and provide individual comparisons. Recap uses the same capture mechanism for how it felt and next steps, including before a transcript exists. Extraction and scoring for voice responses run after commit in a consistent read, outside D2; the source is checked again before returning. Other voice tools are refused in this dedicated private conversation, preventing third-party question text from initiating unrelated actions or retrieving general context.

## Consent, providers and private playback

Archive audio is sent only to the configured transcription provider under R1/R2 consent and budget rules. Real-question voice practice is a separate owner-requested use: its unchecked dashboard confirmation explicitly consents to those questions and new answers being processed by the configured normal voice provider. The confirmation timestamp and exact source revision are saved. Preparing practice makes no paid call. Actual voice still requires the existing cloud consent, budgets, limits and configured routing; no new model, voice, rate or provider path is added. There is no voice cloning.

Optional AI debrief is not exposed. The default review and thank-you draft are deterministic templates; no agent assessment is automatically created, no extra provider is called and nothing is sent. Interview imports and private practice/recap turns remain excluded from general memory, agent context and domain knowledge. A future optional AI debrief must use the existing budgeted, evidence-checked agent mechanism with separate exact run consent and a narrowly reviewed private-source policy; it must not weaken these general exclusions.

Owner-approved weak-question cards use existing learning/scheduling records with private source references and generic text. No question is copied into the general card store. They reopen the unlocked interview page and are excluded from general context selection, agent practice plans, source eligibility and ordinary voice recall. No card is created without approval.

Playback fetches one existing bounded canonical WAV piece from encrypted storage through an owner-only, unlocked, elevated endpoint. It verifies the current transcript revision and Me-piece membership, reads outside D2, then rechecks current metadata before returning. Responses are inline with no-store, without a download link; PCM memory is zeroed after writing the response. The browser uses an authenticated fetch and temporary Blob URL, clearing/revoking audio and private text on hiding, disconnect, refresh or replacement. These are capture pieces, not precisely trimmed answers. A phone Me label is owner supplied and does not isolate voices mixed within its microphone chunk. Existing retention may make audio unavailable while text practice remains usable.

## Deletion and compatibility

Recording or source-transcript deletion retires every derived private conversation and clears voice turns, session messages, earlier-turn summaries, checkpoints, handoff/current-task data, practice/recap references, tool results, approved private cards and their review snapshots. This includes both transcript and recording delete paths, and general retention. Retired conversations reject late captured speech. Metadata/session redaction is transactional with the source purge. Audio deletion failure rolls the database/session changes back; filesystem effects retain R1's documented non-atomic recovery boundary.

Recording mutations can now stage session writes through the existing composite transaction implementation. The recording/privacy/D2 ordering from R4 is retained. PostgreSQL recording deletion relies on its parent foreign-key cascade, rather than redundantly deleting already-cascaded detached chunk rows. Read-only snapshots have no session writer. General session updates now honor explicit checkpoint removals and title changes so private redaction can clear all stored copies.

All new contract fields are optional and omitted when null, preserving legacy JSON shape. There is no new relational migration or native business screen. Existing encrypted drafts, credentials, configuration and recording keys are untouched. Dashboard-session selection is available now; native continuation depends on the subsequent cross-device handoff item. Hardware speech, microphone/loopback quality, long interview timing and pocket operation remain owner acceptance checks. Full release verification and deployment remain governed by B3-1.
