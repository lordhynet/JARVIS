# Training row codec preparation

`RuntimeTrainingSnapshot` is the internal codec for canonical training-unit extraction. It uses existing TrainingAttempt and TrainingOperation records and existing dictionary/request UUIDs. It does not introduce a business entity, identity, counter, service or history. The combined extraction draft maps its distinct RuntimeTrainingRow type to RuntimeTrainingRows, with the two moved dictionaries removed from cold JSON atomically by migration. The earlier preparation PR44 remained inactive; the combined draft requires independent review before merge/deployment.

Only TrainingAttempts and TrainingOperations row kinds are accepted. Both complete dictionaries are required for a change plan. The caller must load the full unit; a scoped target/question subset must never enter this complete-unit diff. Before-images are canonical JSON strings, so nested list mutations and offset-only changes cannot hide behind reference or DateTimeOffset equality. The entire input/after-image validates before a snapshot/plan is returned. Unchanged rows are omitted, retaining their original raw JSON, formatting and unknown fields; changed records use the existing canonical CLR contract. The eventual migration must transfer original raw JSON, not use this codec to normalize historical payloads.

Operation rows are keyed by request UUID, distinct from target AttemptId. Original operation kinds and null/empty purge fingerprints survive; no fingerprint is invented and no live-target FK is assumed. Existing replay/purge business guards remain in TrainingService. Errors are fixed refusals without stored answer text. No grading, retention pruning or receipt expiry is added.

The adapter shares the existing D2/root transaction and SaveChanges with learning/global sequence/source effects; identity snapshots materialize training before detach. Export/count/retention use canonical getters in the existing transactions. Explicit erasure bulk-deletes training rows and skips their tracked diff; general empty-state diffs load previous rows separately. Migration Up/Down preserve raw payloads and post-Up edits/purges. Existing schema compatibility checks cannot fence already-shipped reconnecting writers; operational stopped-writer/backup/recovery/owner gates remain. Cohesive callbacks still load complete units; no50ms/volume/performance claim or private entry is enabled. The combined draft now includes the separate indexed correction port described in SCOPED_TRAINING_CORRECTION.md; deletion and matched volume measurements remain follow-up work.
