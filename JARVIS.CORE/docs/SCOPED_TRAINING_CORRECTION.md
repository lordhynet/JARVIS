# Indexed training-answer correction

`TrainingService.CorrectAsync` uses the existing runtime-store correction port. Its default cohesive implementation and PostgreSQL override share `TrainingCorrection` normalization, legacy receipt hash, replay/refusal/append decision and one `TrainingProjection.ProjectEvents` replay. The transient normalized change and event/sequence inputs are not stored as new histories, receipts or identities. The full-review projection wrapper delegates to the same implementation; review Result bodies are not projection inputs.

PostgreSQL takes the existing privacy/D2 shared gate followed by the RuntimeDocuments singleton writer stamp lock. It reads operation/target by PK, question attempts with the opaque QuestionId predicate, baseline/membership/card by PK, and matching non-included review Event/sequence metadata through the review-card predicate and sequence PK join. All SQL is async and parameterized. Per-row codec validators are reused; a partial query is never applied through the complete-unit adapter. Cold Json, audio and the global sequence control are not loaded or written. One SaveChanges/commit updates only the target attempt, new operation and changed derived card. Concurrent assessment/submit/manual review/delete/erase writers share the same existing locks.

A matching replay validates the receipt then returns the current live attempt without projection reads or writes. Purged receipts refuse409 before target content is read; conflicting reuse refuses409; deleted new target404, deleted replay409, stale revision409. A missing canonical projection baseline refuses409, so privacy-deleted sources cannot be reconstructed. An ordinary missing current card can rebuild from a still-live baseline. Orphan matching receipts refuse409 rather than exposing a dictionary exception. No sequence is allocated.

Selected invalid review identities/ratings/timestamps/negative sequences fail closed. Legacy absent manual sequences remain0; equal-time/equal-sequence ties now use the existing request/attempt UUID as a final shared deterministic key, rather than unspecified row enumeration. Normal chronological/global-sequence order is unchanged. Exact event offsets, timing provenance, duration ticks, baseline membership, canonical assessment history and self-report scheduling rules remain.

Fixed `correction.*` metrics separate target lookup, training selection, learning baseline/history selection, projection, save and commit. The phase fixture keeps deletion and explicitly forced-cold rebuild diagnostics separate, and pure projection timers preload every unit. No private resource identity enters metric tags. Correction and deletion now share one persistence question reader/card writer; deletion's residual cold reasoning cleanup is described in SCOPED_TRAINING_DELETION.md. No50ms or volume/performance acceptance is inferred from SQL shape: question-local histories can still be large, and deletion still hydrates/serializes cold reasoning state. Matched measurements and residual reasoning-storage design remain follow-up gates. No schema beyond the unreviewed extraction migration26, live rollout, owner entry, privacy/consent/budget or Android audio-only boundary changes are included.
