# Owner-operated protected recovery checklist (D1)

This is a recovery gate before real protected owner entry or normal use of a restored instance. Synthetic key/restart tests do not satisfy it. Perform the rehearsal in isolation with writers, provider work, agents, device connections and normal entry unavailable; never run it against live data as a smoke test.

1. Capture a consistent stopped-writer database backup with every active/retained protection key needed by envelopes AND retry proofs. Preserve recording key/volume recovery material where recordings are included. Keep key material private and encrypted; do not print it in commands, logs or reports. Retain the original backup while verifying recovery.
2. Restore database, required keys and applicable encrypted recording volume into the isolated instance. Verify schema compatibility and a synthetic marker decrypted through the restored key path. A database-only restore or an in-memory key-copy test is insufficient; do not remove retained keys still needed by old records/proofs.
3. **Re-apply privacy deletions after restore before resuming use.** A backup taken before a recording/source purge contains its old baselines, cards, answers and receipts. Reconcile erasure/source-deletion requests accepted after that backup using current owner-controlled recovery/audit evidence, and apply them through the supported transactional privacy/recording deletion paths in the isolated instance. Global erasure epoch checks alone do not prove that later individual source deletions were replayed. Do not hand-edit rows or assume an independent durable deletion journal exists. If the required evidence is missing, recovery remains unverified pending owner reconciliation.
4. Verify reconciled epoch/tombstone state and source deletion across current cards AND training baselines, attempts/assessments, reviews/sequences, original creation responses and derived provider caches. Confirm an old source request returns a conflict/retired response and cannot recreate deleted text, including after another restart. Check associated restored recording files through the supported deletion path; reconcile provider-held copies/exports/backups separately. Preserve content-free evidence rather than plaintext source data in the report.
5. Record exact backup/rehearsal source/schema, key IDs (never key material), synthetic marker result, privacy reconciliation evidence and pending acceptance. Normal entry, scheduled/provider work, devices and feature activation require their existing owner/release gates after verified recovery. This checklist grants no deployment, activation, production deletion or live key/configuration permission.
