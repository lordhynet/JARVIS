# Training storage preservation baseline

`TrainingMigrationFixture` provides synthetic non-empty history for storage changes. It reuses the real training, review and recording-purge transitions and the recording privacy fixture. It includes corrected Unicode answers, superseded assessments, a deleted assessed attempt, a skip, absorbed and subsequent manual reviews, recording-purged receipts, an unrelated goal and a shared global sequence. A deliberately injected null fingerprint models older restored data alongside the current empty purge sentinel.

`Training_storage_fixture_survives_current_schema_restore_replay_and_post_restore_edits` captures the current training footprint after stopping its source host: the whole cold runtime document and fingerprint, all shared learning rows, sequence control and synthetic sessions. It restores those rows atomically into a different disposable PostgreSQL database with identical applied migrations and no pending model changes. A fresh host must reproduce the canonical runtime snapshot, including JSON timestamp offsets and retired receipts. Session timestamps use the existing database normalization.

Original successful request IDs replay without changing canonical state or physical root/learning/control MVCC stamps. Deleted requests cannot resurrect attempts; empty and null purged operation fingerprints return `training_operation_purged`. A new correction preserves history, and a subsequent manual review uses the existing sequence authority. A final restart must preserve those new writes too.

The fixture exposed a pre-existing fractional-duration replay defect: the stored `TimeSpan` can lose a tick relative to its input double, so comparing `TotalSeconds` to that original double rejected a valid retry. The shared review decision now compares durations at the existing stored tick precision, using the same conversion as creation. Inputs that differ below that precision represent the same stored duration; changed ticks still conflict. The memory regression covers fractional, sub-tick and boundary values; PostgreSQL restore/replay uses fractional inputs unchanged.

This is a training-footprint regression on the current schema, not a general backup format or an operational recovery rehearsal. Audio, voice, device and protected tables remain default; encrypted keys, recording files and independent post-backup deletion evidence are outside its scope. It does not satisfy the owner-gated D1 checks in [PROTECTED_RECOVERY.md](PROTECTED_RECOVERY.md).

The canonical training-unit extraction design still requires implementation, exact-source review and migration gates. Extend the physical footprint for its new table and reuse the same semantic fixture for Up/Down/re-Up, including edits and purges made after Up. Add malformed/unknown/conflicting-copy refusal, schema compatibility, erasure/export/retention and consumer tests. Extraction and scoped mutation performance must be measured separately; this test makes no latency claim.
