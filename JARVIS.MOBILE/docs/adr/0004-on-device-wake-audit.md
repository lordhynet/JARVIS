# On-device wake audit

The existing owner-enabled local wake mode remains off by default. It uses only createOnDeviceSpeechRecognizer, requires API 31/on-device availability, and has no cloud-recognizer fallback. No microphone audio is buffered for upload or sent before “Hey JARVIS” is detected at the start of an utterance. A question may follow immediately; “the TV said hey Jarvis” is rejected. Core then arbitrates the same global fence used by Windows; only a winner proceeds. Independent visible-app/handoff metadata traffic is not speech recognition traffic.

Android does not promise continuous, low-power keyword detection through SpeechRecognizer: its API is explicitly not intended for continuous recognition. JARVIS re-arms bounded on-device sessions while its owner-enabled microphone foreground notification is present. This is best-effort local wake, not a guaranteed always-on hotword engine. No new recognition package is introduced. Battery drain, false wakes, earbud routing and simultaneous laptop detection require physical acceptance.

This follow-up is based on released development 5c960c8 and retains its WakePausePolicy: lock/screen-off, calls and battery saver pause local wake and resume only when those conditions clear. Existing broadcasts and AudioManager events drive that policy; there is no 5 Hz watcher. JARVIS's own communication route is not treated as somebody else's call. Recording starting/active is different: a StateFlow collector disables wake persistently, and the recorder explicitly stops and waits for listening, arbitration and live voice. Recording never auto-resumes wake; the owner must enable it afterwards. The common stop path cannot re-arm wake during recording. Recognizer stop executes synchronously on the main thread before the recorder observes wake off. A recognizer ERROR_AUDIO stops with a microphone-unavailable message rather than repeatedly reacquiring it.

WakeCandidateAdmission is the actual production path around the Core candidate call and is tested with injected eligibility, request, release and delivery functions. Admission is checked before requesting and again before delivery. A candidate that becomes ineligible due to recording, pause or a changed lifecycle generation is never delivered and its unused lease is released best-effort under a bounded non-cancellable cleanup. If cancellation prevents receiving a server-issued ticket, its existing short Core lease expiry is the remaining recovery boundary. No paid provider attempt is retried.

Microphone foreground service start remains an explicit visible-activity/owner action; restart offers a tap-to-resume notification. Android 14+ while-in-use restrictions prohibit casually starting this microphone service from the background. Existing live voice may use its separate restricted-lock behavior; these stops govern local wake admission. The recording microphone may continue after lock under its own explicit consent, with JARVIS voice/wake excluded.

Official references checked 19 November 2026:
- [SpeechRecognizer API](https://developer.android.com/reference/android/speech/SpeechRecognizer): API 31 on-device factory and continuous-recognition limitation.
- [Foreground service while-in-use restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start): visible-activity starts and microphone restrictions.
- [Foreground service types](https://developer.android.com/about/versions/14/changes/fgs-types-required): microphone service type and permissions.

Before release, JVM/lint/build gates run locally. After the authorised S22 installation, record only checks actually observed; TV false-wake rate, hourly battery drain, earbuds and simultaneous laptop wake remain owner hardware checks. Laptop wake stays off in this release iteration.
